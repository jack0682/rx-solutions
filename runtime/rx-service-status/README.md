# Local service status files

`rx-service-status` is a shared S library for reading initialization/shutdown status of supervisor-owned Host/Executor processes. `READY` means software initialization complete, not P admission or proof of actual device qualification, physical stop or resource handover. `STOPPED` must also be interpreted together with actual exit confirmation for the owned child. `reconciliation_required` is not converted into other authority.

`GuardedStatusBinding` contains the release-specified absolute status-file path and exact role/scope. Host scope is installation UUID, host Name and installation identity Digest. Executor scope is installation UUID, cell Name, assignment service journal UUID and configuration Digest. File envelope `rx.protocol-guarded-status.v1` contains path-free `GuardedScope`, launch instance UUID, PID, positive sequence, source observed_at and `GuardedState`. States are kind-discriminated STARTING/READY/STOPPING/STOPPED/ATTENTION objects.

`Reporter::from_environment(scope)` returns None when `RX_PROCESS_STATUS_PATH` is absent, preserving existing INSTANCE_ID-only usage. Specifying STATUS_PATH requires valid `RX_PROCESS_INSTANCE_ID`. Invalid guarded settings are errors and do not silently fall back to legacy behavior. This path uses actual Linux BOOTTIME and current PID. Other than explicit test/library `Reporter::with_clock` and `Reader::with_clock`, there is no fake-clock fallback through environment variables or files.

`publish(&mut self, state)` increments sequence and records source time. A writer exclusively owns one path through a persistent lock. An existing file can be continued only with identical role/scope/instance/PID; deletion or content replacement between updates is also rejected. A new regular temporary file is created with mode 0600, written with bounded bytes and fsynced, then replaces the file through same-directory rename and directory fsync. Maximum file size is 65,536 bytes. The writer does not schedule heartbeats; Host/Executor own publication at intervals of 250 ms or less.

The parent must be a precreated actual directory. Relative paths, parent/leaf symlinks and special files are rejected. The reader opens with NOFOLLOW/NONBLOCK and checks bounded reads, strict JSON/schema, role/scope/instance/PID and positive sequence. It rejects clocks differing from actual BOOTTIME, future source times and ages beyond 2 seconds. A missing parent or dangling symlink is an error, not None. Only actual leaf absence returns None.

Reads return original source observed_at, sequence and payload digest; repeated query time is not turned into a new observation. The supervisor separately checks sequence/digest regression and changed content at the same sequence across consecutive observations of one instance. Because it creates a unique status path per launch UUID, it does not delete/overwrite old-instance files to adopt them as a new owner.

Unit-test sources cover exact role/owner/configuration, stale/future/clock mismatch, malformed/zero sequence, competing writers/content replacement, symlinks/special files, preservation of already open readers across atomic replacement, clock regression/sequence overflow and legacy-environment compatibility. Actual Host/Executor heartbeats and supervisor readiness/stop judgments are separate integration-test scopes.
