# v1.0 문서 revision 2026-09-14-neutral.1

개정일: 2026-09-14. 사용자 결정에 따라 개인 프로젝트의 제조사 중립 정책을 반영한다. 이 개정은 **문서·장비 포함 정책의 개정**이며 wire semantic version 변경이나 새로운 실행 검증 완료가 아니다.

## 변경과 보존

특정 제품별 기본 지원 표를 장비 능력·제어 구성별 binding 검토로 교체했다. 특정 driver의 종료 효과를 해당 효과가 있는 driver의 공통 요구로 표현했다. profile 의존성은 장비별로 선택한다. 저장소 밖으로 복사되는 규범의 링크는 독립 checkout에서도 읽을 수 있는 GitHub 경로로 바꿨다.

메시지·enum·상태 전이·필드·정규 의도·동일 요청 처리·UNKNOWN·fence·permit·관측·결과/자원 인계의 의미는 유지한다. semantic_version `1.0.0`, wire package `rx.contract.v1`를 유지한다. 기존 기록을 신판 profile로 소급 재해석하지 않는다.

구성 유형을 늘렸다는 이유로 이동·시설·능동 균형 장비의 지원을 검증됐다고 하지 않는다. 실제 모델·mode·firmware·관측·제어권·기동/종료·물품 지지·timing은 해당 profile이 검증해야 한다.

## 반례 검토

- 필요한 package가 설치돼도 제어권·교정·관측이 없으면 admission을 허용하지 않는다.
- driver 종료가 torque disable을 일으키면 물품 지지가 필요한 상태에서 정상 종료하지 않는다. 동작 이름만 중립화해 이 의무를 제거하지 않는다.
- 서로 다른 profile이 같은 controller나 물품을 공유하면 충돌·인계 조건을 공통 자원으로 검사한다.
- 현재 idle·속도 0·mode 수락·통신 정상만으로 과거 완료를 확정하지 않는다.
- 새 schema hash와 옛 hash의 혼합을 semantic_version 문자열이 같다는 이유로 자동 허용하지 않는다.

이는 문서상 의미 대조이며 새 native/실물 시험 결과가 아니다. 이전 검토·시험 원문은 [보존 안내](https://github.com/jack0682/rx_docs/blob/main/references/README.md)에 있다.

기존 운영 설치를 이 문서 정비만으로 업그레이드하지 않는다. 새 설치는 일치하는 신판 구성을 사용한다. 기존 설치의 변경은 원장·profile·peer·증거를 보존한 별도 migration과 전체 호환 검증이 필요하다. 구판 reader 또는 명시적 dual support 없이 과거 기록·서명을 신판 hash로 치환하지 않는다.
