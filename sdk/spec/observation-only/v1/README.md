# Observation-only Host binding — candidate v1

Status: candidate Host boundary plus P internal read-only registration/fact acceptance. The public signed onboarding/resident service path is not yet connected end to end. No physical qualification or full framework acceptance is implied.

A Binding may explicitly include `observation_only` with schema `rx.observation-only-binding.v1` and 1..128 uniquely named source declarations. Each source declares `id`, `schema`, `unit` and `value_type` (BOOLEAN, INTEGER, REAL, SYMBOL or REALS). The `handover/` source namespace is reserved. This declaration is immutable installation input, not a field accepted from a read request.

An observation-only binding has no qualification ID, qualification revision, operation intents, condition IDs or execution purposes. Their empty/absent encodings are omitted. It still identifies the Host/platform/cell/definition/envelope/scopes/environment needed to correlate its read boundary. One Host installation cannot mix observation-only and control bindings in this revision. A legacy binding without observation_only remains control-capable and retains all existing required control fields and validation. Valid legacy JSON canonical encoding is preserved. Rust Binding.qualification is now Option<Id>; source authors constructing control literals must use Some(id), which is a Rust API change.

`rx_host::observation::Provider` supplies only environment, local lifecycle/protection, observe, stop and stop observation. `Adapter::new(provider)` implements the old native surface with command/lookup/handover refusal. Stopping stops new reads, retries a failed stop request, and never fabricates an actuator handover. Its stop report describes read/IO lifetime only; the Host does not report physical shutdown assessed from an observation-only stop.

Host initialization accepts this explicit mode while still refusing an empty legacy control binding. Bootstrap reads permit only declared source IDs and verify each returned source's schema, unit and value kind. Acquisition time, generation, evidence ID, quality and uncertainty are preserved; old samples are not stamped as fresh. Freshness acceptance by P remains a separate responsibility. Before/after native reads, the Host checks that observation service admission has not stopped.

The service reports OBSERVATION_READY. `admission_open` remains the service request-lifetime latch; it is not operation authorization. AcquireGrant, RenewGrant, Arm, Prepare, Authorize, process-configuration acceptance, qualification acceptance and void-before-send are refused for this mode through the control/admission gates. Restrictive cell fencing and authenticated reads remain separate. No grant, permit, Arm or qualification is created to enable observations.

This changes local Host binding/service/API types only. Base/cell/HostRead protobuf numbers and manifest hashes remain unchanged; older P implementations still attempt control bootstrap and will not bind an observation-only Host. A new P-side observation registration/read path must explicitly recognize the declared role, verify transport/source identity and generations, and reuse existing fact validation without constructing a fake HostRegistration or empty grant. Data-only whole cells, IO custody requiring actual hardware resources, generation replacement, field sensor qualification and high-rate control remain separate work.

Verification of this slice must include legacy control behavior, explicit mode without fake authority fields, unknown source/schema/unit/value mismatch, preserved old acquisition metadata, denied command/grant attempts, proper stop, and two external providers through the same authenticated reader. That transport proof is not P registration or task-level completion.


## Candidate revision 2: P read-only source registration

P has a distinct internal observation Link. Its registration input comes from the pinned Host transport adapter, not an HTTP caller-supplied snapshot. It requires a currently authenticated, cell-negotiated producer, fresh actual configuration/read provenance, current definition/envelope/environment and exactly the configured sources. The target Host has no assigned operation steps in this cell; resource fences and pending operations/permits are empty. Existing operating registration/plans cannot be silently adopted. P's role concerns this relationship, and does not prove that an arbitrary remote executable lacks all native actuation capabilities.

The immutable link pins installation/store/runtime generation, producer session/authentication binding, Host boot/journals, cell configuration digest, source generations and transport/binding provenance. A repeated read-only TLS connection can recover that same relation without rewriting its original evidence. Changed producer/source/configuration/pin continuity cannot silently replace it. No normal HostRegistration, grant, fencing request, qualification, mandate or permit is fabricated. Existing operating bootstrap and direct registration reject a current observation-only relationship.

Read ingestion rechecks the relation, producer identity, current configuration and read window before reusing the ordinary batch fact-validation transaction. That shared path now takes only source identity/generations rather than an operating grant. Native acquisition time, evidence, quality and uncertainty remain unchanged. An old but well-formed sample may be recorded; condition evaluation and diagnostics must still classify it as stale. Source generation mismatch preserves the evidence as unusable and invalidates dependents instead of adopting the new source.

The same condition evaluator obtains registered observation generations independently of operating registrations. Diagnostics expose OBSERVATION_ONLY with no grant expiry; it means current observation registration, not operation readiness. This is an additive diagnostic response value that consumers must handle. Revoked producer identity, producer replacement or changed Runtime/configuration cannot make retained samples usable. Producer replacement invalidates observation dependents in its transaction, without inventing the operating Host's resource-rejoin origin.

`rx_host_client::observation_connection::ObservedHost` supplies pinned establishment and read_once through the writer commands. It deliberately exposes no grant/dispatch methods. Its existence/compilation is not proof that a signed package, resident ConnectionService, qualification cohort or external client SDK has been wired to select this path. Those remain integration work.

Replacement/re-registration after a changed source, Host or P generation requires a future explicit supported procedure; revision 2 fails closed and does not clear any restriction. This is containment, not completed restart recovery. The current scope is a fact-only Host in a legitimate action-bearing cell; pure data-only cells, mixed Host modes, physical sensor provenance/IO custody and whole workflow qualification remain separate.
